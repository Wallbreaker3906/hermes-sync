## 会员权益履约追踪

## 背景

船加网（boatplus.cn）的供应商购买会员后享有若干权益。用户（客户运营）需要确保每一项权益按时兑现。此技能覆盖：读取权益清单 → 建立履约追踪表 → 更新进度 → 维护给客户看。

用户工作包含两大板块：产品入驻（由 `product-onboarding` 技能覆盖）和客户权益履约（本技能覆盖）。

## 工作流程

### 1. 确定会员等级与权益清单

从会员等级获取权益列表：
- 黄金会员 ¥20,000/年
- 铂金会员 ¥50,000/年
- 钻石会员 ¥100,000/年

权益模板文件位于 `~/Documents/`，命名格式：【模板】{等级}会员权益事项说明_{日期}.xlsx。

### 2. 为供应商建立追踪表

基于模板，为具体供应商创建追踪表。文件命名格式：
```
~/Documents/【{企业简称}】{等级}会员权益履约追踪_{YYYYMMDD}.xlsx
```
例如：`【欧卡】黄金会员权益履约追踪_20260616.xlsx`

### 3. 进度列及填写规则

在模板末尾追加两列：

| 列 | 标题 | 规则 |
|:--:|------|------|
| H | 进度 | 下拉菜单：`未申请` / `已申请` / `进行中` / `已完成` |
| I | 完成情况简述 | **仅当进度为"已申请"或"已完成"时填写** |

⚠️ **I 列铁律**：I 列是客户会看到的。只有在权益已产生实际成果时才写内容。「进行中」和「未申请」的权益 I 列一律留白——客户不需要看到还没兑现的东西。

进度状态含义：
- **未申请**：客户尚未提出该权益的使用需求
- **已申请**：客户已提出需求，部分交付完成，但剩余额度未启动（如 5 次咨询用了 1 次）
- **进行中**：当前正在活跃推进中（如入驻流程尚未走完）
- **已完成**：权益额度全部用完

**常见错误**：把「已申请」（部分完成但已停滞）标记为「进行中」。区分标准——是否有人在主动推这件事？没人推 = 已申请，有人推 = 进行中。

### 4. 更新追踪表

当权益状态变化时，直接更新 `~/Documents/` 下的追踪表文件。更新后实时打开 Excel 供用户确认。

更新前检查：
- 是否所有权益行都已填写 H 列？容易漏掉跨分类边界的行
- 是否只有「已申请」「已完成」的行 I 列有内容？
- 是否把进度填到了错误的行？（行号偏移是常见 bug，改完后逐行核对）

## Excel 模板变体创建

### 场景
基于现有会员级别模板（如黄金会员权益表），创建另一级别（如铂金）的变体。

### ⛔ 核心铁律：从原版改，不要从零建

**正确做法：**
1. `shutil.copy(原版路径, 新版路径)` — 以原版为基底
2. 用 openpyxl 加载，逐行修改 B 列数值和 F 列备注
3. 删除不需要的行（如铂金无首页中部广告）→ `ws.delete_rows(n)`
4. C/D/E 列（客户面文字）谨慎修改——仅当权益内容实质变化时才改
- **G 列（图片）完全不动**

### ⛔ 删除行后图片锚点错位

`ws.delete_rows(n)` 不会自动调整 TwoCellAnchor 图片的锚点坐标。删除某行后，该行下方的所有图片会整体错位（每删一行偏一行）。

**症状：** 图片出现在错误的内容行旁边，看起来对应关系全乱。

**修复方法：** 遍历所有需要纠正的图片，手动调整 `_from.row` 和 `to.row`：

```python
for idx in [2, 3, 4, 5, 6, 7, 8]:  # 受影响的图片索引
    img = ws._images[idx]
    img.anchor._from.row -= 1  # 上移一行
    img.anchor.to.row -= 1
wb.save(path)
```

**避免此问题的替代方案：** 如果可行，先删除行再插入图片。但实际场景中常常是先有图片再删行（从原版模板派生），此时必须手动修正锚点。

### ⛔ 通用化模板时清除企业名称

从供应商专属表格派生通用模板时，必须检查并替换所有包含企业名称的单元格。用 openpyxl 全表扫描：

```python
for row in range(1, ws.max_row + 1):
    for col in range(1, ws.max_column + 1):
        cell = ws.cell(row=row, column=col)
        if cell.value and '企业简称' in str(cell.value):
            cell.value = str(cell.value).replace('企业简称', '企业会员')
```

**错误做法（实战踩坑）：**
- ❌ 从零建 workbook → 图片丢失
- ❌ 用 `deepcopy` 跨 workbook 拷贝图片 → 尺寸被放大、锚点错乱
- ❌ 试图手动重建格式 → 永远做不到和原版一模一样

### 数值对照
创建变体时，必须**对照会员权益对比图**（用户提供的截图），而不是凭记忆或猜测。OCR 提取的数据需由用户逐项确认后才写入。

常见 OCR 误读陷阱：
- 多列表格中列数据容易串位
- ✓/✗ 符号可能被读成「太」「大」等汉字
- 合并单元格的值可能读错行

### 权益项对齐
- 原版有而新版无的项 → 直接删行
- 原版无而新版有的项 → 需用户明确指示后添加
- **禁止自行增减权益项**

## 权益执行：招标信息定向推送

「政府招标信息定向推送（周推）」是黄金/铂金会员的核心权益之一。执行该权益时：

1. 向用户确认日期区间和船加网帐号
2. 调用 `bid-info-wechat-push` 技能执行完整流程：登录船加网 → 抓取招中标列表 → 摘编排版 → 生成二维码 → 输出推文
3. 推文发布后，更新追踪表中 H 列进度

**注意区分招标和中标**：两者是独立推文，不可混排。中标推文的摘编规则更严格（不得暴露中标方和金额）。

## 重要提醒

- 收到用户发来的文件时，**不要预设它一定属于产品入驻流程**。用户的工作涵盖两个板块：产品入驻 + 客户权益履约。先读内容再判断。
- G 列可能含有图片，不可覆盖或修改。
- 复用型文档第一时间存到 `~/Documents/`，不在缓存目录（`~/.hermes/cache/`）久留。缓存定期清空，文件容易丢失。
