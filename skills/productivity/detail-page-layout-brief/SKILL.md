# 详情图排版任务书生成

## 触发条件
用户说「排版任务书」「详情图任务书」「出任务书」「详情页HTML」「自动出详情图」等。

## 两种交付模式

| 模式 | 输入 | 输出 | 适用场景 |
|------|------|------|----------|
| **A. Word 任务书**（传统） | PDF + SKU表 | Word 文档 → 交设计师排版 | 需要设计师精修、品牌要求极高的 |
| **B. HTML 自动出图**（新版） | PDF + SKU表 + 官网 | HTML → Playwright 截图 1660px PNG | 可快速迭代、标准化程度高的 |

**模式 B 前置条件**：Playwright 已安装（`pip3 install playwright && playwright install chromium`），截图脚本模板见 `references/screenshot_template.py`。

## 核心原则
**不是所有供应商资料都一样。** 产品介绍是唯一固定板块，其余板块均取决于供应商实际提供了什么资料。有什么用什么，没有不强塞。

## ⚠️ 品牌视觉研究（所有模式必做，不可跳过）

**生成任何设计之前，必须先研究供应商的品牌视觉 DNA。** 不研究品牌直接出设计 = 视觉灾难。

### 品牌色提取
1. **官网 CSS**：`curl -sL 官网URL` → 提取 `color`/`background` 等属性中的所有 `#hex` 值，统计使用频率
2. **PDF 宣传册**：用 PyMuPDF 导出首页为像素（`page.get_pixmap(dpi=50)`），对上半部分做像素采样，统计最频繁的 RGB 值，找出品牌主色/深色/浅底
3. **交叉验证**：官网色和 PDF 色可能不同（官网常用 UI 框架默认色），以 PDF 中大面积色块为准

### Logo 获取
从官网 HTML 中搜索 `<img>` 的 `src` 和 CSS `background-image: url()`，关键词 `logo`，下载到 `/tmp/`

### 设计规范固化
提取后输出一张「品牌设计 DNA」卡片：主色 hex、深色 hex、浅底 hex、字体、设计调性描述

## 工作流程

### 0. 确认产品三级分类（防止归错）
- **对于新产品/新增 SKU，必须到 boatplus.cn 验证分类。**
- 方法：`curl -sL "https://www.boatplus.cn/product/product_menu.html"` 获取分类树，按 `cat=` 参数定位正确的一/二/三级分类。
- 电气系统 → cat=162_，船用控制设备 → cat=162_208_，推进控制系统 → cat=162_208_257_。
- 不要凭经验猜测分类名（如「推进遥控系统」实际对应船加网的「推进控制系统」——名称可能略有差异）。
- 如果船加网上找不到独立三级分类（如阀门遥控系统），暂归到最接近的已有分类并标注待确认。

### 1. 分析 SKU 归类表
- 读取 Excel，统计产品系列（按三级分类分组）
- 记录每个系列：SKU 数量、型号、分类名
- **同一供应商可能有多个产品大类**（如倍豪同时有动力装置和电气系统），不同大类的 SKU 数量和 PDF 页面分布差异可能很大，不可套用前一类的结构假设。

### 2. 分析 PDF 宣传册和官网
- 通读 PDF 全文，列出供应商提供了哪些内容板块
- **薄 PDF 必须辅以官网**：PDF 仅 1-2 页时内容有限，浏览官网（如 orca-tech.cn）获取完整产品线、解决方案、企业实力、落地案例等信息
- 常见板块：产品介绍、企业介绍、资质认证、生产能力、应用范围、工程案例、企业荣誉、团队风采等
- **只取供应商实际提供的内容**，没有的板块不编造

### 3. 确定详情图板块结构
采用固定 7 板块编号体系，标注共用/独立：

| 编号 | 板块 | 类型 | 说明 |
|------|------|------|------|
| ① | 产品图片区 | 每系列独立 | PDF 对应页裁取 |
| ② | 工程案例 | 紧跟①，每系列独立 | 有则配，无则用兜底话术 |
| ③ | 企业定位 | 共用 | 所有详情图相同 |
| ④ | 资质认证 | 共用 | 所有详情图相同 |
| ⑤ | 生产能力 | 共用 | 所有详情图相同 |
| ⑥ | 应用船型 | 共用 | 所有详情图相同 |
| ⑦ | 跳转链接区 | — | 按系列分组动态调整 |

**板块取舍原则：** ③~⑥ 取决于供应商 PDF+官网实际提供的内容，没有就跳过。① 必有，② 有案例就用、无案例写兜底话术，⑦ 必有。

**不同供应商内容差异大**：倍豪有 34 页 PDF（企业定位/资质/生产/案例齐全），欧卡仅 2 页 PDF+官网（产品线/解决方案/落地案例/企业实力数据）。详情图结构必须灵活调整，不能套用上家模板。

### 4. 确定跳转链接（矩阵表格）
- **不同企业的产品线不同，链接内容必须灵活分辨**
- 从 SKU 归类表中提取该企业的所有产品分类
- **将系列按产品大类分组**（如全回转类 = 系列1~7，侧推类 = 系列8，特种类 = 系列9，电力类 = 系列10）
- 每组一行，列出 4 档优先级链接：
  - 链接1（最优先）：与本组产品最相关的
  - 链接2：次相关品类
  - 链接3：更远品类
  - 链接4（最后）：如有的话
- 当前 SKU 类型不链接到自身
- 仅 1 个 SKU 的分类不推荐自身，链接数可少于 4
- 链接完整文字：`点击查看：{供应简称} {产品分类名}`
- 按钮样式：浅灰底 + 蓝边框，14-16px

### 5. 工程案例匹配
- 通读 PDF 案例相关页面，列出所有案例
- **只取与当前产品分类相关的案例**，无关的舍去（在任务书中注明「共 X 个案例，其余不取」）
- 用 4 列表格呈现：案例名称 | 船东/船厂 | 关键供货 | 适用系列
- 每个案例标注匹配到哪个/哪些系列
- **无匹配案例的系列**：写一句统一的兜底话术，如「{供应简称} {产品大类}已服务于{常见船型列举}等多种船型」
- 案例紧跟产品图片区（板块②），有则配，无则用兜底话术

### 6. PDF 位置标注
- 每个系列标注产品图在 PDF 中的精确位置：页码 + 方位（如 p14 右侧、p16 上半、p18+p15）
- 共用模块标注来源页码 + 内容描述（如「PDF 第 4 页，含公司简介文字 + 插图」）
- 系列名称附带产品别名/品牌名（如「导管式 · 海豚」「对转式 · 飞龙」），从 PDF 中提取

### 7. 生成缩略图
- 为共用模块各生成一张缩略图（`page.get_pixmap(dpi=60, clip=Rect(...))`）
- **不加边框标注**，纯原图裁取，存到桌面 `排版缩略图/`

### 8. 输出任务书（Word）
**Word：** 横版 A4，微软雅黑 10~11pt，表格 Light Grid Accent 1，白底蓝标题，行距紧凑 Pt(16)。
- 标题：18pt 深蓝（#1F4E79），居中
- 一级标题：14pt 深蓝，加粗
- 正文：10pt，段落间距 2pt
- 使用 `python-docx` 生成，保存到 `~/Documents/`。

**不生成 PDF**——用户使用的是 Word 模板，直接出 Word 即可。
**不生成缩略图**——缩略图由人类排版同事从 PDF 自行裁取，任务书只标注页码。

### 9. 交付
保存到 `~/Documents/`，告知用户。

## 方案 B：HTML 自动生成 + Playwright 截图（推荐，替代人工排版）

**适用场景**：当用户希望减轻设计师同事排版负担时，优先走此方案。HTML 自动生成后截图即可出图，设计师只需最终审美把关。

### B0. 环境准备（一次性）
```bash
pip3 install playwright
~/Library/Python/3.9/bin/playwright install chromium
```
Playwright 不在 PATH 上，完整路径为 `~/Library/Python/3.9/bin/playwright`。

### B1. 从模板生成 HTML
- 复制 `templates/detail-page-html-template.html` 到工作目录
- 替换所有 `{{占位符}}` 为实际内容：
  - `{{PRODUCT_NAME}}` / `{{PRODUCT_SUBTITLE}}` / `{{COMPANY_SHORT}}` / `{{COMPANY_FULL}}`
  - `{{CATEGORY_BADGE}}` / `{{CATEGORY_PATH}}`
  - `{{PRODUCT_INTRO}}` — 产品简介段落
  - `{{SPEC_ROWS}}` — 参数表行，格式：`<tr><td class="label">参数名</td><td class="value">参数值</td><td class="label">参数名</td><td class="value">参数值</td></tr>`
  - `{{FEATURE_CARDS}}` — 特性卡片，格式：`<div class="feature-card"><div class="icon">🔹</div><h3>标题</h3><p>描述</p></div>`
  - `{{LINK_CARDS}}` — 跳转链接，格式：`<a class="link-card" href="URL"><div class="link-label">点击查看</div><div class="link-title">文字</div></a>`
  - 企业共用信息（③~⑥）：`{{COMPANY_POSITIONING}}` / `{{CERTIFICATIONS}}` / `{{PRODUCTION_CAPABILITY}}` / `{{APPLICABLE_VESSELS}}`。无资料的板块直接删除对应 `info-block`。
- 如果 PDF 中有产品实拍图，可将 hero 区 CSS 渐变背景替换为 `<img>` 标签。
- 如果产品系列共用板块（③~⑥）已有已生成的 HTML 片段，直接复用粘贴。

### B2. 截图出图
```bash
python3 ~/.hermes/skills/productivity/detail-page-layout-brief/scripts/screenshot-detail.py /path/to/detail.html
```
输出 1660px 宽 PNG（@2x 视网膜图，直接符合船加网上传标准）。

### B3. 后续：热区提取
截图出图后，衔接 `detail-page-hotspot-extraction` 技能提取可点击热区、生成 HTML 代码。

### HTML 方案优势
- 参数表、特性卡片、链接按钮全部代码生成，零手工排版
- 修改只需改 HTML → 重新截图，秒级迭代
- 共用板块（③~⑥）一次编写、全系列复用
- 深色科技风默认主题，CSS 变量可快速换肤

## 广告法合规
详情图文案中**禁止使用极限词**：首个、第一、唯一、最多、最长、最佳、最高级、全国首个等。
- "首个XX产品" → "XX产品"
- "全国首个获XX认证" → "获XX认证"  
- "数量最多" → "数量领先"
- 注意：PDF 原图中也可能嵌有极限词文字，需要提醒用户处理（PS 修改或裁切）

## 链接设计规则
详情页中的引流链接必须遵守：
- **仅在船加网内部跳转**，不链接外部网站（如企业官网）
- **不链接其他品牌页面**
- **同产品多 SKU 互相引流**：每个版本的详情图只保留一个链接，指向另一 SKU
- 链接放产品名称附近（顶部），不放底部
- 产品未上传时 URL 留空，只需做好按钮样式

## Pitfalls

- ⚠️ **必须先做品牌研究再生成设计**：不研究供应商官网+PDF的品牌色、Logo、设计调性就直接写HTML = 视觉灾难。用户评价"缺少视觉设计的考虑，脱离品牌视觉风格"。正确流程：官网CSS提取配色 → PDF像素采样验证 → 下载Logo → 固化为设计DNA卡片 → 然后才写HTML。
- ⚠️ **链接必须基于真实SKU**：不能凭空编造链接（如"智能清洁船""ORCA-APAS系统"），必须对照SKU表确认哪些产品/分类在船加网上真实存在。新产品用分类检索页链接（如 `?cat=S_01_008_`），已有产品用详情页链接。
- ⚠️ **分类不能靠猜**：新产品/新增 SKU 的三级分类必须到 boatplus.cn 验证。船加网分类名可能和 PDF/内部叫法略有差异（如 PDF 写「推进遥控系统」→ 船加网叫「推进控制系统」）。方法见工作流程第 0 步。
- ⚠️ **品牌视觉风格是供应商自己的品牌风格，不是船加网风格**：提取品牌色时应以供应商的 PDF 宣传册和官网为准。
- ⚠️ **「用户给你看文件」≠「自己去磁盘找」**：用户说「你看看我改的」或直接发文件时，**必须读用户发的文件**（Hermes cache 路径），不要从旧路径找。
- Word 表格内容用 `python-docx` 提取（`doc.tables`），不要只用 `textutil`。
- `python-docx` 在 execute_code 中容易超时；写独立脚本到 `/tmp/` 再用 terminal 执行。
- **搜索 PDF 产品位置**：用 PyMuPDF（`import fitz`），不要用 `pdftotext`。
- ⚠️ **PDF 文字嵌在图片里时用 OCR**：PyMuPDF `get_text()` 返回极少文字时（如只返回标题），文字是嵌入在图片里的。解决方案：`page.get_pixmap(dpi=200)` 导出高分辨率 PNG → 用 Swift Vision OCR（`/tmp/ocr_image`）识别。200dpi 可保证中文识别精度。
- **同一供应商多产品大类**：共用模块（③~⑥）可直接复用。

### 链接设计规则（方案 B）

**核心原则：船加网内部、同一品牌、精准不冗余。**

1. **同一产品的多个 SKU 之间互相引流**：每个 SKU 详情图仅保留**一个**互引链接，指向其姊妹 SKU
2. **链接位置**：放在产品名称下方醒目位置（顶部），不要沉底。青绿色醒目按钮样式
3. **不链接到其他品牌**：所有链接 URL 中的 `brand=` 参数必须与当前品牌一致
4. **不链接到船加网外部**：不出现 `orca-tech.cn` 等外部 URL
5. **不链接到品类全量**：如果某品牌在该品类下只有 2 个 SKU，没必要做"查看全部XX产品"链接——互引已覆盖
6. **企业资质做进详情页内容，不做单独链接**：企业实力、资质认证等内容直接写在详情页板块中
7. **新产品无目标 URL 时**：先把引流按钮样式做好，URL 留待上线后填入

### 设计微调：产品特征色点缀

品牌色（从 PDF/官网提取的主色）用于全局。但如果产品本身有独特的视觉特征色（如沧巡无人艇头部的紫色元素），可在以下位置做**少量点缀**（占整体色彩 5-10%）：
- 板块小标题下划线：品牌色 → 特征色渐变（`border-image: linear-gradient(90deg, #主色, #特征色) 1`）
- 产品亮点卡片左边框：特征色细线
- SKU 互引按钮：特征色半透明底

体量控制在 **5-10%**，其余保持品牌主色不动。核心原则：**特征色来自产品本身，不是凭空发明**。

### 图片选取规则（方案 B）

1. **只选能看清的图**：详情图尺寸下（830px 宽），嵌有多段文字或多张子图的复杂页面完全看不清——**禁用**
2. **确认图片属于本产品**：不能用供应商旧型号的图。如沧巡是今年新船型，不能用 2025 年南海测试图（那是其他型号的）
3. **产品主图优先**：PDF 中产品渲染图/实物图适合作为 hero 区主图（清晰、单一主体）
4. **不用场景图优于用错图**：无法确认图片是否属于本产品时，**宁可不放图、只用文字排版**
5. **场景图优先从官网获取**：PDF 中的场景图可能是旧型号/其他产品线的（如 2025 年测试图属于 390RIB，不是 2026 年发布的沧巡）。官网产品页（如 `/product/unmanned/`）的场景示意图才是本产品的权威来源。提取方法：抓取官网产品页 HTML → 搜索 `/image/product/{产品路径}/` 下的图片文件 → 按拼音文件名识别场景类型（如 `xunluo=巡逻`、`jiuyuan=救援`、`fengdian=风电`、`yangzhi=养殖`、`guangfu=光伏`）
6. **确认图片所属产品**：时间对不上就不能用（如 2025 年测试图≠2026 年新船型）

### 广告法合规审查（生成后必做）\n\n详情页文字是商业宣传物料，受《广告法》第九条第三项约束。生成全部文字后必须全量扫描以下极限词并替换：\n\n| 违规类型 | 示例 | 替换方案 |\n|----------|------|----------|\n| 绝对化用语 | 首个、第一、唯一 | 直接删除或改为「领先」「先进」 |\n| 最高级 | 最×（最多/最长/最大/最高） | 改为「领先」「深厚」「显著」等 |\n| 国家级（非认证名） | 国家级×× | 仅保留政府正式认证全称（如「国家级专精特新小巨人」） |\n\n**注意**：政府认定的正式称号（如「国家级专精特新小巨人」「CCS 型式认可」）本身是合规的认证名称，不属于广告极限词。\n\n### 数据权威性\n\n- **SKU 表 > PDF**：当 PDF 和 SKU 表数据不一致时，以 SKU 表为准（用户已审核过）\n- 示例：海况等级以 SKU 录入数据为准，不盲从 PDF 中的数值

### 方案 B（HTML 截图）专属
- ⚠️ **Playwright 截图不能用 execute_code**：沙盒无 playwright。必须写脚本后用 `terminal()` 运行。
- ⚠️ **@2x 截图关键参数**：viewport 设 830px + `device_scale_factor=2` → 输出 1660px。
- ⚠️ **全页截图**：`full_page=True` + 动态检测 `document.body.scrollHeight`。
- ⚠️ **不要用 hermes_tools.read_file 做文件修改管线**：`read_file` 返回的内容带行号前缀（如 `   123|内容`），直接写入会污染文件。做 HTML 修改时用 Python 内置 `open()` 或 `patch` 工具。
- ⚠️ **macOS 沙盒绕过**：Documents 等目录被 TCC 拦截时，用 `osascript -e 'tell application "Finder" to duplicate file ... to (POSIX file "/tmp" as alias) with replacing'` 将文件拷贝到 /tmp/。
- 模板中的占位符需替换为完整 HTML 片段，不是纯文本。
